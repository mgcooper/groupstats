barchartcats

PURPOSE

BARCHARTCATS Bar chart by groups along x-axis and by color within groups.

SYNOPSIS

function varargout = barchartcats(tbl, ydatavar, xgroupvar, cgroupvar, opts, props)

DESCRIPTION 

BARCHARTCATS Bar chart by groups along x-axis and by color within groups.

 Description

 This function creates a bar chart of the data grouped by specified
 categories.

 Syntax

 h = barchartcats(tbl, ydatavar) creates a bar chart, for column ydatavar in
 table tbl. If tbl.(ydatavar) is a vector, then barchart creates a single bar
 chart. In this mode, BARCHARTCATS behaves exactly like BOXCHART(ydata)
 where ydata = tbl.(ydatavar).

 h = barchartcats(tbl, ydatavar, xgroupvar) groups the data in the vector
 tbl.(ydatavar) according to the unique values in tbl.(xgroupvar) and plots
 each group of data as a separate bar chart. xgroupdata determines the
 position of each bar chart along the x-axis. ydata must be a vector, and
 xgroupdata must have the same length as ydata.

 h = barchartcats(tbl, ydatavar, xgroupvar, cgroupvar, "XGroupMembers",
  xgroupmembers, "CGroupMembers", cgroupmembers) uses color to differentiate
 between bar charts. The software groups the data in the vector ydata
 according to the unique value combinations in xgroupdata (if specified) and
 cgroupdata. It plots each group of data as a separate bar chart. The
 vector cgroupdata then determines the color of each bar chart. ydata must
 be a vector, and cgroupdata must have the same length as ydata. Specify the
 'GroupByColor' name-value pair argument after any of the input argument
 combinations in the previous syntaxes.

 h = barchartcats(_, Name, Value) specifies additional chart options using
 one or more name-value pair arguments. For a list of properties, see
 BarChart Properties.

 Input Arguments:

 tbl - A table containing the data to be plotted.

 ydatavar - The name of the variable in the table tbl that contains the data
 values for the bar chart.

 xgroupvar - The name of the categorical variable in the table tbl used to
 define groups along the x-axis.

 cgroupvar - The name of the categorical variable in the table tbl used to
 define groups for the colors of the bars.

 Method - the method used in the call to groupsummary to compute the values
 plotted as bars. The default method is 'mean'. For 'mean', the standard
 deviation is also computed in the call to groupsummary to support the
 addition of whiskers to the bars. If 'median' is passed in as the method,
 the whiskers represent the interquartile range. Set PlotError to draw
 them. PlotError needs one bar per x-tick, so omit cgroupvar.

 xgroupuse - A cell array of categories to be used for the x-axis grouping.

 cgroupuse - A cell array of categories to be used for the color grouping.

 Parent - The axes to draw into. The default is gca, so repeated calls
 reuse the current axes. The bars, the whiskers, the shading, the
 legend, and the axis formatting all go into this axes, and the
 current axes is not touched when another one is named.

 LegendString - Replacement legend entries, one per color-group member.
 LegendString(i) names the i-th member in category order after member
 filtering and merging. CGroupOrder permutes the entries with the
 series, so an entry stays on its member. SortBy orders the x-groups
 and leaves the legend as it is.

 ShadeGroups - Shade alternating x-tick groups to tell one group of
 bars from the next. Defaults to true when cgroupvar is given and
 false otherwise, because the shading marks a boundary between
 colored bars that a single-series chart does not have. Pass
 ShadeGroups=true to shade a single-series chart anyway.

 MergeGroupMembers - A cell array of string vectors. Each cell names
 the color-group members to pool into one bar, matching
 groupstats.histogram. A bare string vector is one merge group. The
 merged bar's label joins the member names with " and ", and the bar
 takes the position of its first member in the current category order.

 MergeMethod - "pooled" (default) or "membermean". "pooled" summarizes
 the pooled member rows, so the merged bar is the statistic over every
 row of the merged members, and PlotError works. "membermean" is the
 unweighted mean of the member bars' summary values, which weights each
 member group equally regardless of its row count. With Method="mean"
 and equal-sized member groups the two agree. With Method="median"
 they can differ even then, because a pooled median is not the mean of
 member medians. "membermean" discards the spread of the combined
 groups, so PlotError cannot be set with it.

 Output Arguments

 H: A handle to the created bar chart.
 L: The legend, or an empty graphics placeholder when the legend could
    not be created.
 AX: The axes the chart was drawn into.

 Example

 Plot the peak variable of the fixture table. Group along the x-axis by
 month, and by color within each group by scenario.

  data = groupstats.test.generateTestData('info');
  h = groupstats.barchartcats(data.Info, "peak", "month", "scenario");

 Restrict the groups to named members. XGroupMembers and CGroupMembers are
 name-value arguments, not positional ones.

  h = groupstats.barchartcats(data.Info, "peak", "month", "scenario", ...
     XGroupMembers = ["Jan", "Feb", "Mar"], ...
     CGroupMembers = data.scenarios(1:2));

 Sort the x-groups by their group mean and pass a Bar property through:

  h = groupstats.barchartcats(data.Info, "peak", "month", "scenario", ...
     SortBy = "ascend", BarWidth = 0.5);

 Sorting

 SortBy orders the x-groups by their summarized value, "ascend" or
 "descend". The sorted grouping is always xgroupvar. Each x-group's
 sort value is the mean of its bars' heights. SortGroupMembers names
 the cgroupvar members whose bars enter that mean; omitted, or
 string.empty(), it uses every bar. It needs cgroupvar, and each name
 must be one of its members (post-merge names after a merge). XGroupOrder names the order
 directly and takes precedence over SortBy.

 Note

 Grouped data is summarized in category order, not first-appearance
 order. An (x-group, color-group) pair with no rows gets no bar, and
 the other bars stay on their own ticks. A table that is already a
 groupsummary output is summarized again: name its summary column as
 ydatavar, and each bar is then Method over that column's rows in the
 group, with the spread of those rows as the whisker.

 Colors

 Each color group takes the next row of defaultcolors, the palette
 boxchartcats and scatter read, so the k-th color group of any chart
 in the family has the same color. Pass FaceColor to override it, or
 CData to color the bars through the colormap as bar does.

 Dependencies

 These come from matfunclib and must be on the path:

  defaultcolors (libplot)      colors the bars
  dealout (functools)          splits the outputs

 Matt Cooper, 29-Nov-2022, https://github.com/mgcooper

 See also reordergroups, reordercats, barchart,
 groupstats.boxchartcats, groupstats.namelists.sortorder

0371       [~, ic] = ismember(G.(cgroupvar), cmembers);
0372       ncols = numel(cmembers);
0373    end
0374    slot = sub2ind([numel(XData), ncols], ix, ic);
0375    ydata = YData;
0376    edata = EData;
0377    YData = nan(numel(XData), ncols);
0378    EData = nan(numel(XData), ncols);
0379    YData(slot) = ydata;
0380    EData(slot) = edata;
0381 
0382    % cgroupvar may be empty; the logical stand-in makes bar treat
0383    % everything as one color group, matching boxchartcats.
0384    if isempty(cgroupvar)
0385       CData = true(size(YData));
0386    else
0387       CData = tbl.(cgroupvar);
0388    end
0389 end

0392 function [CData, YData] = mergemembermean(CData, YData, mergegroups)
0393    %MERGEMEMBERMEAN Average member columns of the summary matrix by name.
0394    %
0395    % The columns of YData arrive in category order of CData. Each merge
0396    % group's columns average into the first member's category position.
0397    % The shared relabel gives the merged category the same position, so
0398    % the columns and the categories stay paired. The merged column takes
0399    % the minimum member position; a mean position can collide with an
0400    % unmerged column's position.
0401 
0402    % Capture the pre-merge category order, then relabel the rows through
0403    % the shared helper, which also validates the member names.
0404    members0 = string(categories(removecats(CData)));
0405    CData = mergegroupmembers(CData, mergegroups);
0406 
0407    % A bare member list is one merge group, the same rule the helper uses.
0408    if ~iscell(mergegroups)
0409       mergegroups = {mergegroups};
0410    end
0411 
0412    % A member with no rows in an x-group holds NaN there, so the merged
0413    % bar averages the members that exist and is NaN only when none do.
0414    keep = true(1, numel(members0));
0415    for n = 1:numel(mergegroups)
0416       cols = find(ismember(members0, string(mergegroups{n})));
0417       YData(:, min(cols)) = mean(YData(:, cols), 2, 'omitnan');
0418       keep(setdiff(cols, min(cols))) = false;
0419    end
0420    YData = YData(:, keep);
0421 end

0423 function [XData, YData, EData] = reorderXGroups(opts, sortcolumns, ...
0424       XData, YData, EData)
0425    %REORDERGROUPS Reorder the x-axis (tick) groups.
0426    %
0427    % Use this to order categorical data, or data of any type, other than by
0428    % the default ordinal ordering.
0429 
0430    if opts.XGroupOrder == "none"
0431       % The sortorder namelist allows ascend, descend, and none. "stable" is
0432       % a sort option MATLAB accepts and this one does not.
0433 
0434       % A pair with no rows holds NaN, so the mean reads the bars that
0435       % exist, and an x-group with none of the selected bars sorts last.
0436       switch opts.SortBy
0437          case {"ascend", "descend"}
0438             stat = mean(YData(:, sortcolumns), 2, 'omitnan');
0439             [~, idx] = sort(stat, opts.SortBy, 'MissingPlacement', 'last');
0440             XData = reordercats(XData, string(XData(idx)));
0441          otherwise
0442             % "none", the only other value the sortorder namelist allows.
0443             % "stable" was considered and left out: for categories it means
0444             % the order they already have, which is what "none" does.
0445       end
0446    else
0447       % Sort by order of provided elements
0448       % A partial order names some x-groups and leaves the rest behind
0449       % them, the way CGroupOrder does.
0450       members = string(categories(removecats(XData)));
0451       idx = reordergroupmembers(opts.XGroupOrder, members, ...
0452          "barchartcats", "XGroupOrder");
0453 
0454       % reordercats changes the display order and leaves the rows where they
0455       % are. bar pairs XData(i) with YData(i,:), so permuting the rows too
0456       % would move each height onto another group's tick.
0457       XData = reordercats(XData, members(idx));
0458    end
0459 end

0461 function [YData, EData, CData, opts] = reorderCGroups(opts, YData, ...
0462       EData, CData)
0463    %REORDERCGROUPS Reorder the color groups, which are the columns of YData.
0464    %
0465    % bar draws one series per column, and the legend reads them in that
0466    % order. Ordering the columns orders both the bars within each x-tick
0467    % group and the legend. A caller's LegendString binds to the members in
0468    % category order, so it is permuted the same way and stays on its data.
0469 
0470    if isscalar(opts.CGroupOrder) && opts.CGroupOrder == "none"
0471       return
0472    end
0473 
0474    % groupsummary groups by category order, so the columns of YData are in
0475    % category order. unique(...,"stable") would give first-appearance order
0476    % and pair each label with the wrong column.
0477    if iscategorical(CData)
0478       members = string(categories(removecats(CData)));
0479    else
0480       members = string(unique(CData));
0481    end
0482 
0483    idx = reordergroupmembers(opts.CGroupOrder, members, ...
0484       "barchartcats", "CGroupOrder");
0485 
0486    YData = YData(:, idx);
0487    if ~isempty(EData)
0488       EData = EData(:, idx);
0489    end
0490    if numel(opts.LegendString) == numel(members)
0491       opts.LegendString = opts.LegendString(idx);
0492    end
0493 
0494    if iscategorical(CData)
0495       CData = reordercats(CData, members(idx));
0496    end
0497 end

0499 function plotBarErrors(opts, H, YData, EData)
0500    %PLOTBARERRORS Draw one whisker per bar, from the spread of its group.
0501    %
0502    % The whisker is the standard deviation for method "mean", and the
0503    % interquartile range for method "median". summarizeTableGroups computes
0504    % whichever pairs with the method.
0505 
0506    if ~opts.PlotError || isempty(EData)
0507       return
0508    end
0509 
0510    % bar draws on a categorical ruler. That ruler converts any x it is given
0511    % back to a category, so a whisker cannot sit at a fractional offset from
0512    % its tick. With one series per tick the bar center is the tick, and the
0513    % whiskers land correctly. With more, they would all stack on the tick
0514    % center and read as belonging to the wrong bars.
0515    if numel(H) > 1
0516       error('groupstats:barchartcats:plotErrorNeedsOneSeries', ...
0517          ['PlotError needs one bar per x-tick, and this chart has %d. ' ...
0518          'A categorical x-axis places every whisker on the tick center, ' ...
0519          'so they would not line up with their bars. Omit cgroupvar, or ' ...
0520          'leave PlotError off.'], numel(H))
0521    end
0522 
0523    % XEndPoints holds the center of each bar in a series, which is where the
0524    % whisker belongs. Computing it by hand would repeat bar's own layout.
0525    % Take hold after the guard, so the error leaves the axes as it found them.
0526    ax = opts.Parent;
0527    washeld = ishold(ax);
0528    hold(ax, 'on')
0529 
0530    errorbar(ax, H.XEndPoints, YData(:, 1), EData(:, 1), ...
0531       'LineStyle', 'none', 'Color', 'k', 'LineWidth', 1, 'CapSize', 4);
0532 
0533    if ~washeld
0534       hold(ax, 'off')
0535    end
0536 end

0538 function shadebarchartgroups(opts, H)
0539    %SHADEBARCHARTGROUPS Shade alternate x-tick groups, as boxchartcats does.
0540 
0541    if ~opts.ShadeGroups
0542       return
0543    end
0544 
0545    % Each series reports the center of its bars, so the leftmost and
0546    % rightmost across every series bound the group.
0547    xends = vertcat(H.XEndPoints);
0548    xleft = min(xends, [], 1);
0549    xright = max(xends, [], 1);
0550 
0551    if numel(xleft) < 2
0552       return
0553    end
0554 
0555    % XEndPoints lists each x-group in the row order XData held when bar()
0556    % drew it, which is data order, not left-to-right display order.
0557    % reordercats (SortBy or XGroupOrder) changes the display order without
0558    % moving XData's rows, so that order can now disagree with position on
0559    % the axis. Sort the left/right edges by position first, or the gap and
0560    % the alternating selection below read the wrong neighbors and shade
0561    % the wrong ticks.
0562    [xleft, order] = sort(xleft);
0563    xright = xright(order);
0564 
0565    [ylow, yhigh] = bounds(ylim(opts.Parent));
0566 
0567    % Extend each shaded region halfway to its neighbor, so the shading meets
0568    % between groups rather than leaving a gap.
0569    dx = mean(xleft(2:end) - xright(1:end-1), 'omitnan') / 2;
0570    xleft = xleft - dx;
0571    xright = xright + dx;
0572 
0573    idxodd = 1:2:numel(xleft);
0574    xpatch = [xleft(idxodd); xright(idxodd); xright(idxodd); ...
0575       xleft(idxodd); xleft(idxodd)];
0576    ypatch = repmat([ylow; ylow; yhigh; yhigh; ylow], 1, numel(idxodd));
0577 
0578    P = patch(opts.Parent, xpatch, ypatch, 'k', ...
0579       'FaceColor', [0.5 0.5 0.5], ...
0580       'FaceAlpha', 0.1, ...
0581       'EdgeColor', 'none');
0582 
0583    % Put the shading behind the bars, and keep it out of the legend.
0584    uistack(P, 'bottom');
0585    set(get(get(P, 'Annotation'), 'LegendInformation'), ...
0586       'IconDisplayStyle', 'off');
0587 end

0589 function [H, L, ax] = createCategoricalBarChart(XData, YData, CData, ...
0590       cgroups, ydatavar, opts, props)
0591    % Create the barchart. cgroups names one color group per YData column.
0592    % It is read from the categories of CData after any merge relabeled
0593    % them, so the names always match the columns.
0594 
0595    % Note: "grouped" is the default. Use "BarLayout","stacked" for stacked
0596    ax = opts.Parent;
0597    H = bar(ax, XData, YData, props{:});
0598 
0599    % Add a ylabel
0600    ylabel(ax, ydatavar);
0601 
0602    % Format the plot
0603    set(ax, "YGrid", "on", "XGrid", "on", "XMinorTick", "off", "Box", "on");
0604    set(ax.XAxis, 'TickLength', [0 0]);
0605 
0606    % Color the bars
0607 
0608    % The k-th color group takes the k-th row of defaultcolors, the palette
0609    % boxchartcats and scatter read, so the family colors its groups alike.
0610    % The palette holds 21 colors; more series than that wrap around.
0611    colors = defaultcolors();
0612    colors = colors(mod((1:numel(H)) - 1, size(colors, 1)) + 1, :);
0613 
0614    % bar already took the caller's properties, so setting one here would
0615    % discard what they asked for. Apply each default only when they left it
0616    % out.
0617    given = string(props(1:2:end));
0618 
0619    % A caller's CData shows only under flat coloring, so "flat" stands in
0620    % for the palette color when CData is given.
0621    for n = 1:numel(H)
0622       if ~ismember("LineWidth", given)
0623          H(n).LineWidth = 1;
0624       end
0625       if ismember("CData", given)
0626          palettecolor = "flat";
0627       else
0628          palettecolor = colors(n, :);
0629       end
0630       if ~ismember("FaceColor", given)
0631          H(n).FaceColor = palettecolor;
0632       end
0633       if ~ismember("EdgeColor", given)
0634          H(n).EdgeColor = palettecolor;
0635       end
0636       if ~ismember("FaceAlpha", given)
0637          H(n).FaceAlpha = 0.75;
0638       end
0639    end
0640 
0641    % Add the legend
0642 
0643    withwarnoff('MATLAB:legend:IgnoringExtraEntries');
0644    legendtxt = opts.LegendString;
0645    if isempty(legendtxt)
0646 
0647       % If no cgroupvar was provided, CData will be a vector of "true". This
0648       % means a legend is unnecessary, if legendtxt was not provided.
0649       if islogical(CData)
0650          legendtxt = '';
0651          opts.Legend = 'off';
0652       else
0653          legendtxt = cgroups;
0654       end
0655 
0656    end
0657    try
0658       L = legend(ax, legendtxt, ...
0659          'Location', 'northwest', ...
0660          'AutoUpdate', 'off', ...
0661          'Orientation', opts.LegendOrientation, ...
0662          'FontSize', 12);
0663 
0664       set(L, 'Visible', opts.Legend)
0665    catch
0666       % A legend failure must still assign L, or the (H, L, ax) return
0667       % throws on an unassigned output. An empty placeholder matches the
0668       % other charts' legend-failure value.
0669       L = gobjects(0);
0670    end
0671 
0672 end
